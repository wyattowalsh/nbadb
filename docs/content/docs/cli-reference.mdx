## Pipeline commands

These are the commands most operators touch first.

    `--season-end/-e`, repeatable `--format/-f`, `--data-dir/-d`,
    `--verbose/-v`, and `--quality-check`.
  </ScoutCard>
  <ScoutCard title="`nbadb daily`" label="Current-season refresh">

    live-game sources, then rebuilds the stable output universe.
  </ScoutCard>
  <ScoutCard title="`nbadb monthly`" label="Recent multi-season sweep">
    Refreshes the configured recent-season window with season-local player

    rebuilds the stable output universe.
  </ScoutCard>
  <ScoutCard title="`nbadb full`" label="Deprecated">
    **Deprecated.** Use `nbadb backfill run` instead, which provides targeted
    extraction with gap detection, `--dry-run`, and finer control.
  </ScoutCard>

### Run modes that matter most

| Command          | Primary intent                              | Scope                                                                                               |
| ---------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `nbadb init`     | Full historical build                       | Historical seasons from `--season-start` through `--season-end`                                     |
| `nbadb daily`    | Current/open-season recurring refresh       | Recent games, current entities, applicable result routes, live closure, and complete stable rebuild |
| `nbadb monthly`  | Configured recent-season recurring refresh  | Season-local discovery, applicable result routes, live closure, and complete stable rebuild         |
| ~~`nbadb full`~~ | ~~Retry failures and fill historical gaps~~ | **Deprecated.** Use `nbadb backfill run` instead                                                    |

<Callout type="warn">
  **Deprecated commands:** `nbadb full` is deprecated — use `nbadb backfill run`
  for targeted gap-fill. `nbadb run-quality` is deprecated and hidden — use
  `nbadb scan --fail-on error` as the hard assurance gate instead.
</Callout>

<Callout type="warn">
  Daily and monthly return nonzero on incomplete extraction, stable-transform
  failure, or cancellation. Hosted publication proceeds only after scan, export,
  candidate metadata generation, durable GitHub Deployment intent, and exact
  Kaggle readback. `backfill run` remains a targeted recovery surface and does
  not authorize recurring publication by itself.
</Callout>

## Backfill commands

The `backfill` command group provides targeted extraction, gap detection, and journal management. Unlike the pipeline commands above, backfill operates selectively on specific seasons, endpoints, and parameter patterns.

<DataColumns>
  <ScoutCard title="`nbadb backfill run`" label="Targeted extraction">
    Extracts specific endpoints/seasons with `--seasons/-s`, `--endpoint/-e`,
    and `--pattern/-p` filters. Supports `--force` to re-extract,
    `--extract-only` and `--transform-only` for partial runs, and `--dry-run/-n`
    to preview.
  </ScoutCard>
  <ScoutCard title="`nbadb backfill gaps`" label="Gap detection">
    Scans the extraction journal to find missing data. Reports expected vs
    actual counts by endpoint, season, and parameter pattern. Use
    `--output-format json` for CI.
  </ScoutCard>
  <ScoutCard title="`nbadb backfill completeness`" label="Coverage report">
    Aggregated completeness view grouped by season and endpoint. Complements
    `gaps` with summary counts rather than per-entry detail.
  </ScoutCard>
  <ScoutCard title="`nbadb backfill journal`" label="Journal management">
    Show, count, reset, or clear journal entries with `--action/-a`. Filter by
    `--endpoint`, `--seasons`, and `--status` (done/failed/abandoned). Use
    `--yes/-y` to skip confirmation on destructive actions.
  </ScoutCard>
</DataColumns>

### Shared backfill options

| Option               | Short | Description                                                            |
| -------------------- | ----- | ---------------------------------------------------------------------- |
| `--seasons`          | `-s`  | Comma-separated seasons or range: `'2015-16,2016-17'` or `'2015:2020'` |
| `--endpoint`         | `-e`  | Comma-separated endpoint names                                         |
| `--pattern`          | `-p`  | Comma-separated param patterns (e.g. `'game,season'`)                  |
| `--season-types`     | —     | Comma-separated season types for historical season-aware patterns      |
| `--context-measures` | —     | Comma-separated video context measures such as `PTS,AST,REB`           |
| `--data-dir`         | `-d`  | Override default data directory                                        |
| `--output-format`    | `-f`  | Output format: `text` (default) or `json`                              |

### `nbadb backfill run`

Use `--dry-run` to preview what would be extracted without executing:

```bash
nbadb backfill run --seasons 2023-24,2024-25 --endpoint box_score_traditional --dry-run
```

Use `--force` to re-extract entries already marked as done:

```bash
nbadb backfill run --seasons 2024-25 --force
```

Use `--extract-only` or `--transform-only` for partial pipeline runs. These flags are mutually exclusive.

Use `--summary-path` in automation when a machine-readable extraction summary should be written alongside the run output:

```bash
nbadb backfill run --seasons 2024-25 --summary-path artifacts/extract-summary.json
```

Use `--season-types` to constrain the historical season-type contract and
`--context-measures` to select a validated subset of the 78 video measures. An
explicit empty or unknown context-measure set fails before database initialization.

### `nbadb backfill journal`

The journal subcommand supports four actions via `--action/-a`:

| Action  | Description                               | Destructive? |
| ------- | ----------------------------------------- | ------------ |
| `show`  | List journal entries (default, max 100)   | No           |
| `count` | Counts grouped by endpoint and status     | No           |
| `reset` | Reset entries to pending (re-extractable) | Yes          |
| `clear` | Delete matching entries permanently       | Yes          |

Destructive actions require at least one filter (`--endpoint`, `--seasons`, or `--status`) and prompt for confirmation unless `--yes/-y` is passed.

## Inspection and quality commands

<DataColumns>
  <ScoutCard title="`nbadb schema [TABLE]`" label="Discovery">
    With no argument, it lists discovered output tables grouped by prefix. With
    an optional table argument, it shows lineage-style details for that table.
  </ScoutCard>
  <ScoutCard title="`nbadb status`" label="Operational state">
    Shows pipeline watermarks, journal summary, and pipeline metadata. Use
    `--output-format json` for CI or scripts.
  </ScoutCard>
  <ScoutCard title="`nbadb scan`" label="Quality and gap scanner">
    Scans the database for missing data, gaps, and quality issues. Use
    `--fail-on/-F` for the hard assurance gate. `--full-publication` is the
    full-extraction terminal path and requires its checkpoint/manifest evidence.
    Supports `--category/-c`, `--table/-t`, `--severity/-s`, `--report-path/-r`,
    `--output-format/-f`, and `--ci`.
  </ScoutCard>
  <ScoutCard title="`nbadb ask QUESTION`" label="Catalog Q&amp;A">
    Matches a natural-language question to curated warehouse routes with
    route-specific season support and `--limit/-l`. Use `--verbose/-v` for SQL
    provenance and `--strict` to exit non-zero on unsupported or failed queries.
    Requires an existing DuckDB warehouse.
  </ScoutCard>
  <ScoutCard title="`nbadb chat`" label="Chainlit UI">
    Launches the canonical Chainlit catalog Q&amp;A app from
    `chat/chainlit_app.py` using the isolated `chat/pyproject.toml` environment.
    Injects absolute `NBADB_DUCKDB_PATH` / `NBADB_DATA_DIR` so `cwd=chat/`
    cannot mis-resolve the warehouse. Reuses the same guarded runtime as `nbadb
    ask`.
  </ScoutCard>
</DataColumns>

Season support is a route contract: routes accept year plus type, year only, or
neither. When a year-capable route has no explicit year, `ask` executes that route's
immutable visible-rowset maximum probe once for that request. Type-capable routes use
the requested season type or default to Regular Season; year-only routes never add a
type filter. There is no shared or persistent season-probe cache. An unavailable,
empty, or invalid probe falls back to the calendar season with the fixed warning
`Warehouse season lookup was unavailable; used the calendar season.` Malformed years
and unsupported dimensions return `needs_params` without executing SQL and without
SQL hash, season value, or season-source metadata. Explicit seasons require adjacent
ASCII `YYYY-YY` syntax. Slash forms, Unicode digits or dashes, separator whitespace,
and wrong-width or nonconsecutive suffixes are rejected before a warehouse probe or
SQL generation, and a malformed candidate takes precedence over any other valid or
relative phrase. Valid full calendar dates, standalone years, and adjacent
alphanumeric identifiers are not misclassified as seasons.

Both `nbadb ask` and `nbadb chat` fail closed when the configured DuckDB file does not
exist. The chat launcher injects absolute paths before switching to `cwd=chat/`; it
does not initialize a warehouse.

### `nbadb status`

Use `--output-format json` for scripts and CI. The JSON payload contains three top-level keys:

```json
{
  "watermarks": [],
  "journal": {},
  "metadata": []
}
```

### `nbadb scan`

The `scan` command replaces the deprecated `run-quality` with a broader quality
and gap scanner. Use `--fail-on error` when the run must be a hard assurance
gate:

```bash
nbadb scan --category data_quality,missing_table --severity warning --fail-on error
```

- `--category/-c` filters to specific check categories: `cross_table`, `temporal`, `missing_table`, `data_quality`
- `--table/-t` filters by table name prefix (e.g. `fact_box_score`, `stg_`, `dim_`)
- `--severity/-s` sets the minimum severity to display: `error`, `warning`, `info`
- `--fail-on/-F` exits non-zero when findings meet or exceed a severity threshold
- `--report-path/-r` writes the full JSON report to a file
- `--output-format/-f` switches between `text` (default) and `json`
- `--ci` enables GitHub Actions integration (step summary + annotations)
- `--full-publication` makes every declared conformed and silver/gold game, roster, team, box-score, play-by-play, shot, standings, draft, aggregate, and analytics anchor mandatory and enforces declared row-preserving silver-to-gold cardinality pairs; the full-extraction route supplies the exact checkpoint evidence below
- `--checkpoint-report` supplies the terminal checkpoint JSON whose lane, run, coverage, blocked-evidence, and zero-error inventories must account for the full extraction manifest
- `--checkpoint-manifest` and `--checkpoint-dir` supply the exact manifest and checkpoint database consumed by the canonical verifier; staging and journal row counts are recomputed from that database
- `--checkpoint-chain-id` and `--checkpoint-source-sha` bind that proof to the expected extraction chain and 40-character source commit
- `--successor-generation-store` is a legacy private-generation validation option retained by the older experimental path; the one-repository daily/monthly workflow does not use it

### `nbadb contract-assurance`

Use this command to compile the provider, parser-input/bronze, staging-route,
star-table, field-fate, temporal, and metric contracts into one exact local
pre-extraction assurance generation:

```bash
uv run nbadb contract-assurance \
  --profile pre-extraction \
  --endpoint-analysis-docs-root /path/to/nba_api \
  --check
```

`--endpoint-analysis-docs-root` is required and must name a readable local
exact-source `nba_api` checkout. The command performs no network access. `--profile`
currently accepts `pre-extraction`, and `--output-root` selects the parent for
brand-new generation directories.

The recurring contract uses public-safe request/result/header-or-path/ordinal/
value/presence/provenance landings plus committed receipts. Exact decoded-body
capture is optional bounded diagnostic material and is not a baseline, resume,
assurance, or publication dependency.

With `--check`, the command writes two distinct fresh generations beneath the output
root, validates each exact member and parent digest, and requires their semantic
digests to match. Its terminal summary separates four different claims:

```text
Structural generation: GREEN
Semantic determinism: GREEN
MODEL-GREEN: RED
DATA-GREEN: UNPROVEN
Generation semantic SHA-256: <64-hex-digest>
Assurance location: second_fresh_generation_directory
```

Structural green means the declared contract generation is complete and internally
consistent; it does not make unresolved model semantics or populated data green.
`contract-assurance` is a MODEL diagnostic, never a DATA gate: exit 0 means
MODEL-GREEN, exit 1 means MODEL-RED or a local generation failure, and exit 2 means an
unsupported profile. The local DATA result is always UNPROVEN here — hard DATA
assurance comes only from the remote-readback and human-verification receipt chain —
so no workflow may treat this command's exit status as publication DATA authority. The
current inventory is deliberately `MODEL-GREEN: RED`, so the command exits with code
1 after printing its blockers even when structural generation and semantic
determinism are green. `DATA-GREEN: UNPROVEN` is independent and does not claim an
extraction, live-availability, publication, or remote-readback result.

### `nbadb extract-completeness`

By default this writes coverage artifacts to `artifacts/endpoint-coverage/`:

- `endpoint-coverage-matrix.json`
- `endpoint-coverage-summary.json`
- `endpoint-coverage-report.md`

Pass `--output-dir` to change the destination.

Pass `--endpoint-analysis-docs-root` only when ingesting the full upstream
`nba_api` contract surface. Point it at the root of a complete upstream
checkout containing both `docs/**` and `tools/**`; a copied docs subtree will not
produce complete source inventory or contract artifacts.

When enabled, the upstream contract artifact set includes:

- `endpoint-analysis-doc-contracts.json`
- `endpoint-analysis-doc-diff.json`
- `endpoint-analysis-doc-upstream-contract-diff.json`
- `nba-api-upstream-contract-bundle.json` with source inventory, file digests,
  docs/tools metadata ledger summaries, malformed-doc warnings, and a stable
  bundle digest
- `nba-api-bronze-contracts.json` with generated bronze table contracts derived
  from upstream stats/static docs and tools metadata plus installed
  `nba_api.live.nba.endpoints.*.expected_data` for live endpoints. Rendered live
  docs contribute supplemental URL, validation-date, and field-description
  metadata only; they are not the canonical live table-shape source.

Use `--require-full` in CI to fail when any hard readiness gate remains open:

- extraction readiness blockers: partial or blocked endpoints, or open
  season-type contracts
- upstream contract blockers: field gaps, invalid result-set indices, missing
  result-set staging, missing input schemas, or unclassified/unknown result sets
- field-fate blockers: missing sinks, unknown model usage, or unclassified
  unmodeled fields
- temporal blockers: required temporal coverage gaps
- endpoint-analysis docs blockers, when `--endpoint-analysis-docs-root` is
  supplied: docs discovery failures, docs-only endpoints/result sets, invalid
  result-set indices, docs/runtime field drift, missing result-set staging, or
  missing input schemas
- docs/tools metadata blockers, when `--endpoint-analysis-docs-root` is
  supplied: parse or ingestion warnings from the full upstream docs/tools tree,
  tool endpoints missing parsed docs, docs endpoints missing from the tool
  endpoint list, or generated zero-column bronze result sets

Use `--require-model-contract` to fail when a staged stats surface still lacks an explicit downstream decision. The command summary prints separate counts for analytically modeled, passthrough-only, compatibility/reference-only, explicitly excluded, and still-unowned surfaces.

That endpoint-level contract is intentionally separate from the output-schema audit. The same summary now prints **star schema coverage** counts for transform outputs so you can see, independently, how many tables have a schema-backed final-tier contract versus how many still bypass star-schema validation.

### `nbadb endpoint-support-matrix`

Use this when you need the strictest repo-local answer to "is every endpoint wired into the repo contract, and what kind of downstream ownership does it have?"

```bash
uv run nbadb endpoint-support-matrix --require-complete --require-season-type-contract
```

By default this writes companion artifacts next to `extract-completeness` under `artifacts/endpoint-coverage/`:

- `endpoint-support-matrix.json`
- `endpoint-support-summary.json`
- `endpoint-support-report.md`

It also refreshes the shared endpoint-coverage bundle in that directory, including the adequacy scorecard, so CI can gate the full contract from a single regeneration pass.

The command distinguishes three execution semantics:

- `historical_backfill` for stats/static surfaces that can be rebuilt from their earliest supported season or date
- `reference_snapshot` for reference/static snapshots
- `live_snapshot` for append-only live feeds such as scoreboard, odds, live play-by-play, and live box score packets

Use `--require-complete` to fail whenever any endpoint remains only partially wired into staging, transforms, or schemas. The summary also breaks downstream semantics into analytically modeled, passthrough-only, compatibility/reference-only, explicitly excluded, and unowned buckets so compatibility surfaces do not get mistaken for full analytical ownership. Use `--require-season-type-contract` to fail whenever a historical surface still lacks explicit season-type semantics or remains deliberately blocked from that contract.

### `nbadb endpoint-adequacy-scorecard`

Use this when you want the endpoint-centric view that combines extraction coverage, support contract state, and downstream ownership into a single scorecard:

```bash
uv run nbadb endpoint-adequacy-scorecard
```

By default this writes companion artifacts next to `extract-completeness` under `artifacts/endpoint-coverage/`:

- `endpoint-adequacy-scorecard.json`
- `endpoint-adequacy-scorecard-report.md`

If you already regenerated `endpoint-support-matrix` or `extract-completeness`, those shared coverage runs also refresh this scorecard; use this command when you only need the adequacy pair itself.

The scorecard surfaces endpoint-level adequacy, downstream ownership, execution semantics, and the underlying coverage/support gap counts so you can quickly see whether each endpoint is analytically modeled, passthrough-only, compatibility/reference-only, explicitly excluded, or still unowned.

### `nbadb audit-models`

Use this when you need the end-to-end model contract, not just endpoint completeness:

```bash
uv run nbadb audit-models --mode inventory --strictness consistency
```

The command writes model-audit artifacts under `artifacts/model-audit/` by default:

- `inventory.json`
- `matrix.json`
- `report.md`
- `result-table-inventory.json`

`probe`, `build`, and `full` modes also emit:

- `live-probes.json`
- `build-validation.json`

When `--baseline` is provided, the command also writes `baseline-comparison.json` and enables `no-regressions` or `zero-gaps` enforcement. Pass `--require-result-table-contract` to fail when any runtime result table is still missing from staging, unowned downstream, or only weakly classified because schema coverage is incomplete.

Use the strictness levels progressively:

- `consistency` fails on discovery and audit-contract inconsistencies
- `no-regressions` compares the current inventory summary against a committed baseline, including new result-table contract failures
- `zero-gaps` requires both a baseline and zero remaining audit problems or result-table contract failures

The result-table inventory keeps warehouse ownership semantics explicit per runtime result set:

- `modeled` — analytically modeled with non-passthrough ownership
- `passthrough_only` — owned only by passthrough/union surfaces
- `compatibility_reference_only` — intentionally retained for compatibility/reference visibility
- `excluded` / `deprecated` — explicitly non-modeled but still visible
- `unowned`, `weakly_classified`, and `missing` — contract failures that should be fixed or explicitly classified

For CI canaries, keep `--mode probe` and use the repository’s configured canary profile so PRs exercise each source kind and parameter pattern without running the full live matrix.

### `nbadb docs-autogen`

Use this when generated reference pages drift from code:

```bash
uv run nbadb docs-autogen --docs-root docs/content/docs
```

Use check mode in CI or pre-commit validation:

```bash
uv run nbadb docs-autogen --docs-root docs/content/docs --check
```

Generation removes obsolete legacy `docs/lib/generated/{raw,staging,star}.json`
files. Check mode reports those files as stale if they are present.

It regenerates:

- `schema/{raw,staging,star}-reference.mdx`
- `data-dictionary/{raw,staging,star}.mdx`
- `diagrams/er-auto.mdx`
- `lineage/lineage-auto.mdx`
- `docs/lib/generated/{raw,staging,star}-reference.json`
- `docs/lib/generated/{raw,staging,star}-dictionary.json`
- `docs/lib/generated/{schema,lineage,schema-coverage,agent-catalog}.json`
- `docs/lib/site-metrics.generated.ts`
- `docs/table-profile.generated.json` when `data/nba.duckdb` exists

The same generator is also available via:

```bash
uv run python -m nbadb.docs_gen --docs-root docs/content/docs
```

The command prints `updated:` or `unchanged:` for each artifact, then a final summary line.

### `nbadb schema-annotation-audit`

Use this after schema, staging-route, or bronze-contract changes to regenerate
the machine-readable field fate and annotation audit artifacts:

```bash
uv run nbadb schema-annotation-audit --strict
```

When validating the full upstream bronze surface, pass the generated bronze
contract artifact or the upstream docs root and require the bronze evidence:

```bash
uv run nbadb schema-annotation-audit \
  --bronze-contracts-path artifacts/endpoint-coverage/nba-api-bronze-contracts.json \
  --require-bronze-contracts \
  --strict
```

Strict mode fails on missing descriptions, unresolved routes, invalid foreign
keys, helper/public registry leaks, transform/schema parity gaps, and required
bronze contract absence, disabled state, zero-table output, or zero-column
tables.

## Shared behavior for pipeline commands

These notes apply to `nbadb init`, `nbadb daily`, and `nbadb monthly`.

- `--data-dir` overrides the default data directory (`data/nbadb`) and the `NBADB_DATA_DIR` setting.
- `--quality-check` runs post-pipeline quality checks against the DuckDB file, but those checks are informational today: empty-table warnings are reported without failing the command.
- If stdout is an interactive terminal and `--verbose` is **not** set, the CLI uses the Textual TUI.
- Use `--verbose` to force plain log output and DEBUG-level logging.
- A single `Ctrl+C` or TUI stop is non-success (exit 1). Journal/checkpoint state may support a matching local retry, but it is not a public baseline or publication authority. Pressing `Ctrl+C` again forces exit, still as non-success.
- A successful run prints a summary like this:

```text
daily: 12 tables, 245,901 rows, 38.4s
```

| Flag or default      | Applies to                                  | What to remember                                                                                  |
| -------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `--data-dir/-d`      | Most commands that read or write local data | Overrides the default `data/nbadb` directory and the `NBADB_DATA_DIR` setting                     |

## Data and output defaults

- Default export formats come from `NbaDbSettings.formats`: `sqlite`, `duckdb`, `csv`, and `parquet`.
- `nbadb init` and `nbadb export` use all configured formats when you omit `--format`.
- `nbadb download` copies the Kaggle dataset into the target data directory and seeds `nba.duckdb` from `nba.sqlite` if only SQLite is present.
- `nba.duckdb` is the canonical analytics database; `nba.sqlite` remains the Kaggle preview-friendly relational file.
- `nbadb upload` ensures `dataset-metadata.json` exists, stages only declared files/directories into a temporary upload root, supports partitioned Parquet resource directories, rejects symlinks and path traversal, writes `logs/kaggle/kaggle-upload-manifest.json`, and then publishes the staged bundle. Remote verification defaults to a 3,600-second deadline and 15-second poll interval, paginates the exact-version file inventory, and streams each resource through SHA-256 readback.
- With `--verify-remote`, the marker resolver must return an exact positive Kaggle version. The client then paginates that version's complete API file list and streams every file through SHA-256 readback. Only a marker-specific HTTP 404 can bootstrap one upload after metadata-API version resolution; other baseline failures stop before upload. Any unresolved dataset upload blocks every later bundle until exact evidence resolves it. Local-ledger recovery uses retained `logs/kaggle/kaggle-publication-state.json`; automated publishing also persists that file as secondary evidence while GitHub Deployments provides durable admission. The full-extraction workflow scopes that secondary cache to the current workflow run ID so only a later attempt of the same run can restore it.
- With `--full-publication`, upload additionally requires a valid assured artifact manifest and declared terminal assurance report. The full-extraction schema-v3 report binds chain, source, effective coverage, checkpoint, and blocked-evidence identities. This mode implies `--verify-remote`. Recurring workflows use `--verify-remote` plus the GitHub Deployment ledger over their scanned, exported, metadata-complete candidate.
- In the full-extraction publisher, the assured archive is fetched only after its exact artifact ID, name, canonical archive digest, size, unexpired state, archive URL, producing attempt one, and producing `GITHUB_SHA` match the immutable upload receipt and a final current-owner re-read passes. A later owner attempt is permitted only through the explicit publication-recovery roles — exact cross-run `pending` takeover (record, claim, resolve with a durably terminal origin, takeover receipt plus artifact member, and stable double inventory evidence) or no-upload `in_progress` reconciliation — and may reuse, but not produce or replace, that attempt-one authority. Archive and assured-manifest verification then precede Kaggle staging.
- `--publication-ledger` defaults to `local`. `github-deployment` is the GitHub Actions release mode and requires exact remote verification; `--require-durable-intent` additionally fails closed unless that external ledger is active. Durable mode requires the Actions context, `GH_TOKEN`, `actions: read`, `deployments: write`, `NBADB_KAGGLE_PUBLICATION_SOURCE_SHA`, default-head enforcement, and the exact non-cancelling `nbadb-kaggle-publish` job mutex. The local ledger, process mutex, and host lock do not provide crash- or cross-host-durable admission.
- Full extraction grants its publisher `actions: write` for post-publication metadata closeout. After exact upload or reconciliation, metadata head `M` must be the frozen source or one direct, non-merge, byte-reproducible `dataset-metadata.json`-only child with the fixed commit subject. A child `M` is accepted only after an explicitly dispatched `.github/workflows/ci.yml` run is directly bound to `M` and its fully paginated inventory contains exactly one successful `workflow-lint`, `lint`, `metadata`, `typecheck`, `docs`, and `test` job. Each job is direct-verified and the default ref must still equal `M`; an unchanged source skips CI but still records metadata closeout.
- `nbadb schema` groups tables by output prefix. Analysis-ready convenience outputs use the `analytics_*` prefix.
